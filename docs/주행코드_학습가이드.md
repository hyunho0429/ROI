# MORAI 자율주행 주행 코드 학습 가이드

이 문서는 현재 `morai_ws`에 구현된 GPS·IMU 기반 localization, EKF, MGeo 경로,
Pure Pursuit, MORAI UDP 제어 코드를 순서대로 학습하기 위한 자료이다.
코드를 한 번에 모두 읽기보다, 각 단계의 입력 토픽과 출력 토픽을 확인하면서
다음 단계로 넘어간다.

## 1. 최종 주행 데이터 흐름

```text
MORAI GPS UDP ─┐
               ├─ morai_udp_bridge ─> /gps, /Imu
MORAI IMU UDP ─┘          │
                          v
                 gps_mgeo_converter
                          │ /localization/gps
                          v
                    ekf_local_enu
                          │ /localization/odometry
                          v
                    purepursuit_mgeo
                          │ /ctrl_cmd
                          v
                 morai_udp_drive_bridge
                          │ EgoCtrlCmd UDP
                          v
                        MORAI
```

차량 상태 UDP `/Ego_topic`은 실제 MORAI 위치와 EKF 결과를 비교하는 검증용이다.
Ground truth 성격의 EgoVehicleStatus를 EKF 입력으로 사용하지 않는다.

현재 주행에 사용되는 핵심 입력과 출력은 다음과 같다.

| 구분 | 토픽 | 메시지 | 의미 |
|---|---|---|---|
| GPS 원시 변환 결과 | `/gps` | `morai_msgs/GPSMessage` | 위도·경도·고도 |
| IMU 원시 변환 결과 | `/Imu` | `sensor_msgs/Imu` | 자세·각속도·가속도 |
| MGeo GPS 결과 | `/localization/gps` | `nav_msgs/Odometry` | GPS의 MGeo map 좌표 |
| EKF 결과 | `/localization/odometry` | `nav_msgs/Odometry` | Pure Pursuit가 사용할 차량 pose |
| Pure Pursuit 제어 | `/ctrl_cmd` | `morai_msgs/CtrlCmd` | 속도·조향·제동 명령 |

## 2. 먼저 이해할 좌표계와 단위

### map

MGeo 경로와 GPS 변환 결과가 사용하는 고정 좌표계이다.
현재 코드는 WGS84 위도·경도를 UTM Zone 52N으로 변환한 뒤 다음 local origin을 뺀다.

```text
local_origin_utm = [302595.0, 4124145.0, 0.0]
```

현재 구현의 축은 다음과 같다.

```text
map x: 동쪽 방향(ENU East)
map y: 북쪽 방향(ENU North)
map z: 위쪽
```

### base_link

차량 뒤 차축 중앙을 원점으로 정의한다.

```text
x: 차량 전방
y: 차량 좌측
z: 위쪽
```

현재 센서 외부 파라미터는 다음과 같다.

```text
gps_link: [0.0, 0.0, 1.2] m
imu_link: [0.0, 0.0, 0.0] m
센서 roll/pitch/yaw: 모두 0도
```

따라서 현재 GPS 변환은 GPS의 x, y를 base_link와 동일하게 보고 z에서 1.2 m를
차감한다. 실제 센서 장착 위치가 바뀌면 `config/sensor_extrinsics.yaml`과
통합 launch의 static TF를 함께 수정해야 한다.

### 주요 단위

| 값 | ROS 내부 단위 | MORAI UDP 원본/목적 단위 |
|---|---|---|
| GPS 위도·경도 | degree | NMEA degree-minute 형식 |
| GPS 위치 | m | 변환 후 m |
| IMU 각속도 | rad/s | rad/s |
| IMU 선가속도 | m/s² | m/s² |
| `CtrlCmd.velocity` | m/s | UDP 전송 시 km/h |
| `CtrlCmd.steering` | rad | UDP 전송 시 최대 휠각 대비 -1~1 |
| 차량 휠베이스 | m | 3.000 |
| 최대 앞바퀴각 | rad | 40도 = 0.6981317008 rad |

## 3. 패키지별 학습 순서

### 3.1 `morai_udp_bridge`: UDP를 ROS 메시지로 변환

위치:

```text
src/localization/morai_udp_bridge/
```

읽는 순서:

1. `src/morai_udp_bridge/protocol.py`
2. `scripts/morai_udp_bridge_node.py`
3. `launch/morai_udp_bridge.launch`

`protocol.py`의 역할:

- GPS NMEA `$GPRMC`, `$GPGGA` 파싱
- GPS 1028바이트 패딩 패킷과 실제 길이의 짧은 NMEA 패킷 처리
- IMU 115바이트 형식 처리
- IMU 107바이트 레거시 형식 처리
- IMU `data_length=80`과 `data_length=88` 처리
- MORAI quaternion `(w,x,y,z)`를 ROS quaternion 필드로 변환하기 위한 값 준비

`morai_udp_bridge_node.py`의 역할:

- UDP GPS 포트 `3001` bind
- UDP IMU 포트 `4001` bind
- GPS를 `/gps`로 publish
- IMU를 `/Imu`로 publish
- GPS와 IMU header timestamp를 Ubuntu 수신 시각으로 통일

학습 명령:

```bash
rostopic echo -n 1 /gps
rostopic echo -n 1 /Imu
rostopic hz /gps
rostopic hz /Imu
```

확인할 내용:

- GPS `status`가 1 이상인지
- 위도·경도가 0이 아닌지
- IMU quaternion norm이 1에 가까운지
- 정지 상태에서 z축 가속도가 약 9.81 m/s²인지
- GPS와 IMU의 header stamp가 현재 Ubuntu 시간인지

### 3.2 `gps_mgeo_converter`: GPS를 MGeo map 좌표로 변환

위치:

```text
src/localization/gps_mgeo_converter/
```

읽는 순서:

1. `src/gps_mgeo_converter/coordinate.py`
2. `scripts/gps_mgeo_converter_node.py`
3. `launch/gps_mgeo_converter.launch`

계산 순서:

```text
위도·경도
  -> WGS84 UTM Zone 52N
  -> local_origin_utm 차감
  -> GPS 센서 위치 보정
  -> /localization/gps 발행
```

이 노드는 IMU yaw를 사용해 GPS 센서의 x, y lever arm을 회전시킬 수 있다.
현재 GPS x, y가 0이므로 평면 위치 보정은 없다.

학습 명령:

```bash
rostopic echo -n 1 /localization/gps
rostopic echo -n 1 /gps_mgeo
```

MGeo 경로와 `/localization/gps`가 같은 좌표 범위에 있어야 한다.
차량이 움직이지 않아도 GPS 값이 계속 흔들릴 수 있으므로, 한 번의 값보다
몇 초 동안의 평균과 변동 폭을 확인한다.

### 3.3 `ekf_local_enu`: GPS와 IMU를 융합

위치:

```text
src/localization/ekf_local_enu/
```

상태 벡터는 다음과 같다.

```text
x = [map_x, map_y, yaw, forward_velocity, gyro_bias_z, accel_bias_x]
```

예측 단계:

```text
IMU gyro_z       -> yaw 예측
IMU accel_x      -> 속도·위치 예측
```

보정 단계:

```text
/localization/gps x, y -> 위치 보정
IMU quaternion yaw     -> yaw 보정
```

초기화는 첫 번째 유효한 GPS를 기준으로 한다. 초기 yaw는 가능한 경우 IMU
orientation을 사용하고, IMU yaw가 없으면 GPS 속도 방향을 사용한다.

읽을 함수:

- `imu_callback`: IMU 수신과 시간 간격 계산
- `gps_callback`: GPS 초기화와 위치 보정
- `predict`: IMU 기반 상태 예측
- `update_position`: GPS x, y 보정
- `update_yaw`: IMU yaw 보정
- `publish`: odometry, pose, TF 발행

학습 명령:

```bash
rostopic echo -n 1 /localization/odometry
rosrun tf tf_echo map base_link
```

로그의 다음 값들을 관찰한다.

```text
EKF pose map=(x, y) yaw=... deg v=...
```

정지 상태인데 `v`가 크게 증가하면 IMU 가속도 축·timestamp·bias 설정을 먼저
확인한다. GPS가 튀면 EKF covariance와 GPS position variance를 확인한다.

### 3.4 `purepursuit_mgeo`: MGeo 경로 추종

위치:

```text
src/control/purepursuit_mgeo/
```

읽는 순서:

1. `src/purepursuit_mgeo/path.py`
2. `scripts/purepursuit_mgeo_node.py`
3. `launch/purepursuit_mgeo.launch`

계산 순서:

```text
/localization/odometry 수신
  -> 경로에서 가장 가까운 점 탐색
  -> 현재 속도에 따른 lookahead 거리 계산
  -> 목표점을 base_link 좌표로 변환
  -> 곡률 계산
  -> 앞바퀴 조향각 계산
  -> /ctrl_cmd 발행
```

현재 기본값:

```text
wheelbase       = 3.0 m
lookahead_min   = 4.0 m
lookahead_gain  = 0.35
target_speed    = 2.0 m/s
max_steering    = 0.6981317008 rad
control_rate    = 20 Hz
```

중요한 동작:

- `enable_control=false`: 경로 계산과 시각화만 수행하고 `/ctrl_cmd`를 발행하지 않는다.
- `enable_control=true`: `/ctrl_cmd`를 발행한다.
- `/localization/odometry`가 없으면 계속 대기한다.
- 차량 기준점은 앞 범퍼가 아니라 뒤 차축 중앙이다.

### 3.5 `morai_udp_drive_bridge`: ROS 제어 명령을 MORAI UDP로 변환

위치:

```text
src/localization/morai_udp_drive_bridge/
```

역할:

- MORAI EgoVehicleStatus UDP 181바이트 수신
- `/Ego_topic` 발행
- `/ctrl_cmd` 구독
- ROS 속도 m/s를 UDP 속도 km/h로 변환
- ROS steering rad를 최대 휠각 대비 -1~1로 변환
- 명령이 0.5초 이상 끊기면 정지 패킷 송신

현재 EgoVehicleStatus는 검증용이며 EKF 입력으로 사용하지 않는다.

## 4. 단계별 실습

### 실습 1: 빌드와 패키지 확인

```bash
cd ~/morai_ws
source /opt/ros/noetic/setup.bash
rosdep install --from-paths src --ignore-src -r -y
catkin_make
source devel/setup.bash

rospack find morai_udp_bridge
rospack find gps_mgeo_converter
rospack find ekf_local_enu
rospack find purepursuit_mgeo
rospack find morai_udp_drive_bridge
```

### 실습 2: 실제 센서와 localization만 확인

```bash
roslaunch morai_bringup morai_udp_ekf_purepursuit.launch \
  morai_host_ip:=192.168.0.151 \
  control_remote_port:=9093 \
  enable_control:=false
```

이 단계에서는 차량 제어가 비활성화되어 있어야 한다. GPS·IMU·EKF 결과만 확인한다.

```bash
rostopic hz /gps
rostopic hz /Imu
rostopic hz /localization/gps
rostopic hz /localization/odometry
```

### 실습 3: Pure Pursuit 계산 확인

```bash
rostopic echo /control/lookahead_point
rostopic echo /control/steering_preview
```

`enable_control=false`인 경우 `/control/steering_preview`는 나오지만 `/ctrl_cmd`는
발행되지 않는다.

### 실습 4: 실제 제어 활성화

센서와 EKF가 정상인 경우에만 실행한다.

```bash
roslaunch morai_bringup morai_udp_ekf_purepursuit.launch \
  morai_host_ip:=192.168.0.151 \
  control_remote_port:=9093 \
  enable_control:=true
```

확인:

```bash
rostopic echo /ctrl_cmd
```

`/ctrl_cmd`의 `velocity`는 ROS에서 m/s이다. 예를 들어 `2.0`은 MORAI UDP로
7.2 km/h로 변환된다.

### 실습 5: MORAI ground truth와 EKF 비교

```bash
rostopic echo /Ego_topic
rostopic echo /localization/odometry
```

EgoVehicleStatus는 정답에 가까운 시뮬레이터 상태이고, EKF는 GPS·IMU만으로
추정한 결과이다. 둘의 위치 차이와 yaw 차이를 기록해 GPS-MGeo 정렬을 검증한다.

## 5. 자주 발생한 오류와 원인

### `Pure Pursuit가 /localization/odometry를 기다리는 중이다.`

앞단의 `/gps`, `/Imu`, `/localization/gps`, EKF 중 하나가 나오지 않는 상태이다.
다음 순서로 확인한다.

```bash
rostopic hz /gps
rostopic hz /Imu
rostopic hz /localization/gps
rostopic hz /localization/odometry
```

### `IMU data_length expected=80, actual=88`

MORAI 버전의 data_length 차이이다. 현재 파서는 80과 88을 모두 허용한다.

### `GPS expected=1028, actual=77`

MORAI가 NMEA 문장을 실제 길이 그대로 보내는 경우이다. 현재 파서는 1028바이트
패딩 패킷과 짧은 NMEA 패킷을 모두 허용한다.

### `could not convert string to float: '$(arg gps_xyz_x)'`

rosparam 안의 launch 인자 치환이 되지 않은 경우이다. 현재
`gps_mgeo_converter.launch`에는 `subst_value="true"`가 적용되어 있다.

### 차량이 움직이지 않는다

다음 실행 옵션을 확인한다.

```bash
enable_control:=true
```

`false`는 localization과 Pure Pursuit 계산만 검증하는 모드이다. 또한 MORAI의
제어 목적지 포트가 현재 launch의 `9093`과 일치해야 한다.

## 6. 코드 학습 과제

다음 질문에 답할 수 있으면 기본 주행 코드 흐름을 이해한 것이다.

1. `/gps`와 `/localization/gps`의 차이는 무엇인가?
2. GPS가 들어오는데 `/localization/odometry`가 없는 경우 어느 노드를 확인해야 하는가?
3. EKF에 EgoVehicleStatus를 넣지 않는 이유는 무엇인가?
4. Pure Pursuit에서 wheelbase 3.0 m가 필요한 이유는 무엇인가?
5. `target_speed_mps=2.0`이 MORAI UDP에서 몇 km/h가 되는가?
6. `enable_control=false`일 때 어떤 토픽이 나오고 어떤 토픽이 나오지 않는가?
7. GPS 센서가 뒤 차축 중앙에서 x 방향으로 1 m 앞에 장착되면 어떤 변환을 수정해야 하는가?
8. `/ctrl_cmd`가 나오는데 차량이 움직이지 않으면 ROS 내부와 UDP 구간을 어떻게 분리해 확인할 것인가?

## 7. 현재 구현의 범위

현재 코드는 GPS·IMU localization과 MGeo Pure Pursuit 주행을 우선 완성한 상태이다.
카메라·LiDAR의 인식 결과가 `/ctrl_cmd`에 자동으로 반영되는 안전정지 게이트는
아직 별도 구현 대상이다. 따라서 다음 단계에서는 detection 결과를 control에
연결하는 `safety_stop` 또는 `control_mux`를 설계한다.
