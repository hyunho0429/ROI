# MGeo와 대회 경로 분석

## 현재 보유 자료

공식 MGeo 원본을 다음 위치에 보관했습니다.

```text
morai_ws/data/mgeo/R_KR_PR_K-city_2025/
├─ global_info.json
├─ link_set.json
└─ node_set.json
```

현재 받은 파일은 MGeo 전체 데이터 중 지도 전역정보·링크·노드 자료입니다.
차선 경계, 신호, 도로 객체까지 필요한 경우에는 대회측 원본 폴더의 나머지
JSON도 같은 지도 버전 폴더에 추가해야 합니다.

대회 경로는 다음 파일로 관리합니다.

```text
morai_ws/data/routes/2026_molit_comp_global_path.txt
```

현재 작업폴더의 기존 `data/2026_molit_comp_global_path.txt`는 아직 원래
위치에 남아 있으며, 새 구조에서 사용할 기준 경로로 이후 정리할 예정입니다.

## 현재 경로의 수치 분석

경로는 공백으로 구분된 `x y z` 형식입니다.

| 항목 | 측정값 |
|---|---:|
| waypoint 수 | 4,430개 |
| 첫 번째 점 | `(-131.689798, -428.331023, 28.543960)` |
| 마지막 점 | 첫 번째 점과 동일 |
| XY 경로 길이 | 약 2,184.61 m |
| X 범위 | `-159.242 ~ 75.414 m` |
| Y 범위 | `-550.494 ~ 345.790 m` |
| Z 범위 | `28.106 ~ 28.593 m` |
| 평균 간격 | 약 `0.493 m` |
| 최대 간격 | `0.500 m` |

첫 점과 마지막 점이 같으므로 폐곡선입니다. 경로 인덱서에서 마지막
중복점으로 길이 0인 구간이 만들어지지 않도록 처리해야 합니다.

이 값은 위경도가 아닌 미터 단위의 지도 좌표입니다. GPS local ENU와 바로
비교하지 말고, 지도 원점과 축 방향을 확인한 뒤 하나의 변환만 적용해야
합니다.

## global_info.json 분석

확인된 주요 값은 다음과 같습니다.

| 항목 | 값 |
|---|---|
| MGeo 버전 | `3.0` |
| 전역 좌표계 | `+proj=utm +zone=52 +datum=WGS84 +units=m +no_defs` |
| 작업공간 좌표계 | 전역 좌표계와 동일한 UTM Zone 52/WGS84 |
| `local_origin_in_global` | `[302595.0, 4124145.0, 0.0]` |
| `workspace_origin` | `[40.0, -174.0, -925.0]` |
| 데이터 출처 | 웨이즈원 |
| 라이선스 | MORAI |
| lane-change link 포함 | `false` |

즉, MGeo의 전역 좌표는 UTM 52N 기반이고, 시나리오 파일은 이 지도를
`scenarioCoordinateSystem=ENU`로 사용합니다. `workspace_origin`을 GPS
원점으로 바로 사용하지 말고, 실제 MORAI GPS 패킷과 경로를 한 번 측정하여
변환 관계를 확인해야 합니다.

## link_set.json과 node_set.json 분석

- node 수: 480개
- link 수: 634개
- link geometry point 수: 75,416개
- link point X 범위: `-404.516 ~ 112.354 m`
- link point Y 범위: `-775.046 ~ 571.222 m`
- link point Z 범위: `27.143 ~ 37.380 m`
- node point X 범위: `-396.378 ~ 80.523 m`
- node point Y 범위: `-775.046 ~ 569.528 m`

link에는 시작·종료 node, points, 차선 폭, 차선 변경 가능 여부, 최대·최소
속도, 도로·차선 유형, 신호 연결 정보, link 길이가 들어 있습니다.

## 대회 경로와 MGeo의 일치 여부

대회 경로 4,430개 점을 MGeo link points와 비교한 결과, 모든 점이 6자리
소수점 기준으로 MGeo link point에 일치했습니다.

- 경로 점 일치율: `4,430 / 4,430`
- 경로가 통과하는 고유 link 수: 72개
- 첫 경로 link: `A2256W000748`
- 마지막 경로 link: `A2256W000748`

따라서 이 경로는 MGeo와 별개로 임의 생성된 경로라기보다, MGeo link
geometry에서 추출·샘플링된 경로로 판단할 수 있습니다. 다음 단계는 단순
좌표 변환보다 경로 점을 link ID와 순서에 매칭하고, 주행 방향과 차선 정보를
붙이는 것입니다.

## 샘플 시나리오와 시작점

샘플 시나리오의 Ego 시작점은 경로 첫 점에서 XY 기준 약 `0.422 m`, 첫
경로 구간 방향과 yaw 차이는 약 `1.22°`입니다. 경로 시작점과 차량 시작
자세가 이미 잘 맞춰진 샘플입니다.

시나리오의 지도 정보는 `R_KR_PR_K-city_2025`, UTM52N, ENU로 되어 있어
현재 MGeo의 `global_info.json`과 일치합니다. 자세한 시나리오 구성은
`샘플_시나리오_분석.md`를 확인합니다.

## MGeo가 들어온 뒤의 분석 순서

1. `global_info.json`에서 좌표계, 원점, 단위, 축 방향, 지도 버전을 기록합니다.
2. 실제 제공된 JSON 파일 목록과 필드 구조를 확인합니다. 파일 이름과
   구성은 MGeo 버전에 따라 다를 수 있습니다.
3. MGeo의 link/lane geometry와 대회 경로를 같은 XY 그림에 표시합니다.
4. 경로 각 점을 가장 가까운 link에 매칭하고 횡방향 오차와 방향 오차를
   계산합니다.
5. 시작점, 진행방향, 폐곡선, 고도 기준, 절대좌표/local 좌표 여부를
   확인합니다.
6. 확정된 변환과 경로 버전을 YAML과 분석보고서로 고정합니다.

## 최초 검증 기준

- GPS 단독: 위치와 이동 후 yaw가 안정적인가
- GPS+IMU: 짧은 GPS 끊김에서 위치가 튀지 않고 복구되는가
- 경로 표시: 차량 시작 위치에서 경로의 첫 점과 진행방향이 맞는가
- 카메라 4대: 각 포트의 frame 수, 해상도, timestamp가 정상인가
- LiDAR: 전후·좌우·상하 축과 전방 ROI가 맞는가
