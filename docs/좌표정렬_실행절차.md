# GPS에서 MGeo map으로 정렬값을 검증하는 실행 절차

## 1. 목표

이번 실험의 목표는 다음 변환을 실제 MORAI ROS 기록으로 계산하는 것이다.

    GPSMessage -> 임시 GPS ENU -> MGeo map

개발 검증 기준은 /Ego_topic의 EgoVehicleStatus.position이다. MORAI 문서상
이 위치는 ENU 기준이므로, 같은 시각의 GPS 변환 결과와 비교한다.

최종 결과 파일은 config/localization_alignment.yaml에 저장한다.
검증이 끝나기 전까지 localization.yaml의 transform_validated는 false로 유지한다.

## 2. 반드시 준비할 것

Ubuntu에서 다음 환경이 준비되어야 한다.

- ROS1이 실행 중
- beta_drive 기준 morai_msgs가 catkin workspace에 빌드됨
- rosbridge가 실행 중
- MORAI가 샘플 시나리오를 로드하고 Play 가능
- /gps, /Imu, /Ego_topic이 실제로 발행됨

### 토픽 확인

    source /opt/ros/noetic/setup.bash
    source ~/morai_ws/devel/setup.bash
    rostopic list
    rostopic type /gps
    rostopic type /Imu
    rostopic type /Ego_topic
    rosmsg show morai_msgs/GPSMessage
    rosmsg show morai_msgs/EgoVehicleStatus

다음 타입이 아니면 기록을 중지하고 topic remap부터 수정한다.

    /gps       morai_msgs/GPSMessage
    /Imu       sensor_msgs/Imu
    /Ego_topic morai_msgs/EgoVehicleStatus

## 3. 첫 번째 기록: 정지 상태

정지 상태에서는 위치 원점과 GPS 분산만 확인한다. GPS course로 yaw를 결정하지 않는다.

1. MORAI 샘플 시나리오를 시작점에 배치한다.
2. 차량을 움직이지 않고 10초 이상 둔다.
3. 아래 명령으로 기록한다.

    cd ~/morai_ws/data/rosbags
    rosbag record -O alignment_stationary.bag /gps /Imu /Ego_topic /clock

4. 최소 10개 이상의 GPS 메시지와 여러 개의 EgoVehicleStatus가 기록됐는지 확인한다.
5. 기록을 종료한다.

## 4. 두 번째 기록: 저속 직선

정지 상태에서는 yaw를 안정적으로 구할 수 없으므로, 차량을 짧게 직진시켜 GPS 이동 방향과 Ego heading을 비교한다.

1. 동일한 시작점에서 새로 시작한다.
2. 차량을 저속으로 5~10 m 직진시킨다.
3. 좌우 조향을 크게 넣지 않는다.
4. 다음 명령으로 기록한다.

    cd ~/morai_ws/data/rosbags
    rosbag record -O alignment_straight.bag /gps /Imu /Ego_topic /clock

5. 정지 후 기록을 종료한다.

첫 번째 기록과 두 번째 기록을 같은 bag에 섞지 않는다. 정지 기록은 위치 분산,
직선 기록은 yaw와 축 방향 검증에 사용한다.

## 5. 기록 직후 확인

    rosbag info alignment_stationary.bag
    rosbag info alignment_straight.bag

확인할 항목:

- /gps가 10개 이상 존재하는가
- /Imu가 연속적으로 존재하는가
- /Ego_topic이 연속적으로 존재하는가
- 세 토픽의 timestamp가 같은 시간 범위인가
- /clock을 실제로 사용했다면 clock 메시지가 존재하는가

bag 파일은 MORAI PC가 아닌 Ubuntu 기준 경로에 먼저 저장한다. 이후 이
workspace의 data/rosbags로 복사하거나 경로를 알려준다.

## 6. 계산에 사용할 기준값

### 정지 위치

정지 구간에서 다음을 계산한다.

    gps_mean = GPS map 변환 결과의 평균
    ego_mean = EgoVehicleStatus.position의 평균
    position_residual = gps_mean - ego_mean

GPS 측정값의 각 축 표준편차가 0.5 m 이하인지 먼저 확인한다. 분산이 큰데
정렬값부터 계산하면 잘못된 평행이동을 고정할 수 있다.

### 평행이동

정지 구간의 임시 GPS ENU 평균과 Ego map 평균을 사용한다.

    t_xy = ego_mean_xy - gps_mean_xy

회전이 아직 검증되지 않은 첫 단계에서는 임시 yaw 회전을 0으로 두고
위치 잔차를 계산한다. 위치 잔차가 크면 UTM offset·축 순서·GPS field 해석을
먼저 확인한다.

### yaw 회전

직선 기록에서 GPS 위치 변화량으로 진행 방향을 계산한다.

    yaw_gps = atan2(delta_y_gps, delta_x_gps)
    yaw_ego = EgoVehicleStatus.heading을 map yaw 기준으로 변환
    dyaw = wrap(yaw_ego - yaw_gps)

GPS course가 GPSMessage에 직접 포함되어 있다면 해당 field의 단위와 기준축을
확인한 뒤 사용할 수 있다. field가 없거나 불명확하면 GPS 위치 변화량을 사용한다.

## 7. 통과 기준

아래 값은 개발용 시작 기준이며 대회 공식 판정값이 아니다.

| 항목 | 기준 |
|---|---:|
| 정지 GPS 각 축 표준편차 | 0.5 m 이하 |
| GPS map과 Ego map 잔차 | 1.0 m 이하 |
| 직선 주행 yaw 잔차 | 3도 이하 |
| MGeo 경로 초기 횡오차 | 1.0 m 이하 |
| 보정값 안정성 | 정지·직선 반복 실험에서 같은 값 |

하나라도 실패하면 transform_validated를 true로 바꾸지 않는다.

## 8. 결과 파일에 기록할 내용

계산이 끝난 뒤 config/localization_alignment.yaml에 다음을 기록한다.

- 어떤 bag에서 계산했는지
- MORAI map/scenario 이름과 버전
- GPSMessage 실제 field 이름과 단위
- GPS 임시 원점 정의
- map 변환의 yaw와 XY translation
- 정지 위치 표준편차
- GPS와 Ego 기준값의 평균·최대 잔차
- 직선 yaw 잔차
- 계산 날짜
- transform_validated 여부

## 9. 검증 후 EKF 연결

정렬값이 통과하면 EKF는 다음 순서로 사용한다.

1. /gps를 GPSMessage field 기준으로 map 좌표로 변환
2. 저장된 localization_alignment.yaml의 평면 변환 적용
3. /Imu로 50 Hz 예측
4. /gps로 위치 보정
5. /Ego_topic은 계속 기록하되 EKF 업데이트에는 넣지 않음
6. /localization/status에 GPS health와 정렬 상태 출력

GPS가 끊기는 실험에서는 /Ego_topic으로 보정하지 않는다. IMU 예측만으로
연속성이 유지되는지 확인해야 한다.
