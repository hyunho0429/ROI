# dev/test_highway 안전 제어 수정

기준: `dev/merged_code`의 `c44d8b0` 전체 코드.

- 같은 차로의 앞차와 범퍼 간격이 음수여도 앞차를 제외하지 않고 긴급 정지를 유지한다.
- 차선 변경, 안쪽 차로 유지, 복귀 중에는 매 주기 현재 차량 위치부터 남은 경로의 충돌을 예측한다. 이미 지나온 경로의 이동 시간을 다시 더하지 않으며, 시작점과 처음 2m도 검사한다.
- 복귀 시작과 완료, 기존 경로로 바로 전환하는 경우에도 장애물 정보의 유효성, 충돌 검사, 긴급 정지 및 기존 경로의 정지 신호를 반영한다. 거절된 복귀를 바로 전환하는 분기로 우회하지 않는다.
- 카메라 정보만 끊겼고 기존 경로와 거의 일치하는 경우에는, 장애물 정보와 두 경로의 안전성이 확인되면 기존 직접 복귀 기능을 유지한다.
- 새 ROS 노드의 실행 권한과 `catkin_install_python` 등록을 추가했다. 보조 Python 모듈은 devel/install 실행 디렉터리에 실제 파일로 배치하고 메시지·실행 의존성을 선언했다.

## 로컬 회귀 테스트

저장소 루트에서 Linux/ROS 환경:

```bash
PYTHONPATH="$PWD/src/control/purepursuit_mgeo/src${PYTHONPATH:+:$PYTHONPATH}" \
  python3 -m unittest discover -s src/control/purepursuit_mgeo/test -v
```

ROS 통신을 모의 객체로 대체하고 실제 노드의 판단 및 상태 전환 메서드를 실행한다. 안전 회귀 17개와 기존 경로 추종 1개가 통과했다. 앞차 접근, 목표 차로 장애물, 카메라 단절, 오래된 장애물 정보, 복귀 전환의 정지 유지 및 정상 복귀를 포함한다.

## 검증 범위

Windows에서 회귀 테스트, Python 구문, launch/package XML 및 실행 파일 등록을 확인했다. ROS/catkin 빌드와 MORAI 주행은 실행하지 않았다. 동적 충돌 예측은 기존 등속 모델과 차량 박스 근사를 사용하며, 실제 가감속·조향 응답은 시뮬레이터에서 추가 검증해야 한다. 시작 구간의 충돌 검사 면제를 제거했으므로 가까운 LiDAR 박스에 대한 정지가 이전보다 보수적이다.

ROS 환경에서는 `catkin_make` 후 `devel/setup.bash`를 불러오고 다음 launch를 사용한다. 기본값은 제어 비활성화 및 목표 속도 2m/s다.

```bash
roslaunch purepursuit_mgeo morai_avoidance_highway_roundabout_final.launch enable_control:=false
```

## 비스듬한 차선 변경 및 경로 연결

차선 변경의 횡방향 진행률을 변경했다. 시작과 끝의 각 20%는 부드럽게 방향을 바꾸고, 가운데 60%는 거의 일정한 기울기로 옆 차로로 이동한다. 경계선을 0.5m 간격으로 보간해 카메라의 먼 첫 샘플 때문에 진입 곡선이 생략되지 않게 한다. 초기 차로 중심 오차도 완만한 이동 구간에 포함한다.

최종 launch의 설정:

| 설정 | 값 | 의미 |
|---|---:|---|
| `change_min_length_m` / `change_max_length_m` | 32 / 40m | 차선 변경 구간 길이 |
| `change_max_heading_deg` | 8° | 직선 도로에서 계획하는 대각선 기울기의 상한 |
| `change_ramp_ratio` | 0.20 | 진입·종료 완화 구간 비율 |
| `inner_path_blend_time_s` | 1.0초 | 카메라 경로 보정의 지수 필터 시정수 |
| `inner_path_max_jump_m` | 0.75m | 전방 5/8/12m에서 이전 경로와의 차이 허용치 |
| `steering_rate_limit_rad_s` | 0.20rad/s | 고속도로 전략 활성 중 조향 명령 변화량 제한 |

차로 폭과 초기 위치 때문에 지정 길이 안에서 완만한 경로를 만들 수 없으면 후보를 거절한다. 기존 간격·TTC·충돌 검사를 통과해야 차선 변경을 시작한다. 완료 시에는 실제 차량이 경로의 최종 차로 구간에 도달했고 위치 오차와 방향 오차가 기존 허용치 이내인지 확인한다.

카메라 경로는 이전 경로와 같은 좌표계에서 비교하고 작은 차이는 점진적으로 반영한다. 크게 튀는 중심선은 기존 경로를 잠시 유지하면서 기다린다. 오류가 유예 시간을 넘겨 지속되면 기존 안전 정지는 유지한다. 조향 제한은 `/highway_lane_strategy/active`가 참인 동안 적용하며 정지 명령을 지연시키지 않는다.

추가 검증 후 전체 테스트 33개 통과. 아래는 직선 도로, 차로 폭 3.5m, 이상적인 bicycle 운동 모델, Pure Pursuit를 사용한 비교이며 MORAI 주행 결과가 아니다. 기존 경로는 `c44d8b0`의 최종 launch 설정, 변경 경로는 위 설정을 사용했다.

| 속도 | 기존 최대 진행각 | 변경 최대 진행각 | 변경 후 종료 횡오차 |
|---|---:|---:|---:|
| 2m/s | 13.34° | 8.12° | 0.026m |
| 6m/s | 10.87° | 6.53° | 0.034m |

계획 기울기와 실제 추종 차량의 진행각은 다르다. 타이어·조향 지연·곡선 도로·센서 잡음은 이 모델에 포함하지 않았다. 변경 구간이 길어졌으므로 실제 도로에서 사용할 수 있는 차선 변경 거리도 확인해야 한다.
